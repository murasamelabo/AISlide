# Consulting And Decision Meetings

## Outcome

Enable a specific, evidence-supported decision, not merely a completed reading. The deck's governing message must specify what should change and why. A one-page decision can skip the multi-page logic ledger, but not evidence or validation. This is an edited English adaptation of the user's supplied workflow; no third-party sample artwork or template is bundled.

## Intake

Ask for the decision owner, meeting purpose, alternatives, available facts, material unknowns, decision deadline, constraints, audience expertise, and expected number of pages. Keep unknown values as `xx`. Use blue 1976D2 unless the requester supplies a brand color. A missing business deadline must not become an invented date.

## Claim

Use the common Claim rules strictly. A headline combines evidence with judgment: a recommendation, limiting condition, warranted assessment, or distinction. Test whether a reader could write the same sentence by simply naming the picture; if so, the interpretation is missing. Do not count items as the message, use a slogan instead of a sentence, or state an unsupported outcome as certain.

## Logic

Spend most planning effort on the governing message and logical ledger before drawing. The supplied time guideline is approximately 70%, not a performance guarantee. Multi-page decks carry **3-6 stable decision issue IDs**. Introduce those IDs in an executive summary with requested decisions, evidence and analysis-page references. Resolve the same IDs in the final page with owner, timing and decision criteria. Do not leave the close as a light thank-you page.

The automated compiler provides dedicated `C02` summary and `C03` closing templates. Analysis pages use `native-part` with an explicit core preset. The full 48-pattern catalog preserves selection guidance and recommended components. `composition-required` and `guidance-only` entries are not exact automatic templates and cannot be passed as if implemented. Build them through explicit native editing or select an implemented alternative and acknowledge the difference.

## Pattern Selection

Use the message's verb: decide, decompose, compare, show change, locate a relationship, explain a timeline, or map a structure. Inspect the catalog's input needs and composition requirements before choosing. Examples:

- Compare alternatives on a shared scale, with identical category positions and denominator.
- Decompose a total only when every contribution reconciles; annotate the action responsible for the largest contribution.
- Show a process with visible stage panels and an explicit handoff, keeping the label away from arrowheads and notches.
- Show an issue tree with real parent-child grouping; operators belong on quantitative decomposition branches, not an unqualified organization chart.
- Show a decision matrix using axes that actually affect the decision; accompany it with the decision rule.
- Show a plan with owners, dates, current position, and clearly distinct completed/planned work; do not imply that a generic Gantt preset implements every convention.

## Draw

Use the common reference geometry and restrained primary-color tints. A source, premise, and implication are distinct. Do not add a full-width inference band: put the implication in the headline. Only decision pages may include a concise question box. The automated summary/closing grids use purpose-sized columns, a compact header and editable grouped text, fills and rules, not screenshots or equal-width PowerPoint table cells.

For quantitative comparisons, identify the measure, scale limits, units, period, and relevant source before rendering. For qualitative assessments, name the rubric and who assessed it; do not fabricate scores to fill a chart. Prefer bar, waterfall, table, or matrix to an arbitrary pie.

## Measure And Review

Read only the headlines; reconstruct the conclusion and issue sequence. For each clause, point to the evidence element. Reconcile every headline number. Confirm that parallel pages use one classification and comparable units. Confirm summary/close issue identity and referenced analysis pages. Then inspect typography, collisions and actual PPTX output.

Human review remains mandatory for whether a recommendation follows from evidence, whether the alternatives are complete, and whether the decision authority is correct. The compiler checks structure and provenance declarations, not factual authenticity. One repair pass may address a known problem; an unresolved requirement is reported as unmet, never hidden.

## Review Options

Offer two or three meaningful refinements: stronger sensitivity analysis, clearer decision thresholds, or a more explicit execution owner/date. Do not offer arbitrary decorative changes as a substitute for reasoning.
