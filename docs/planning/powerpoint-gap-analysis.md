# PowerPoint 機能との Gap 調査

調査日: 2026-09-17

対象実装: AISlide `main` / `d19b18b056f0bca64bffb1bf02794abcc2af8591`

比較基準: Microsoft 365 版 PowerPoint の Windows デスクトップ版。Mac、Web、モバイルは同一機能ではない。Copilot、共同編集、保護機能はライセンス、接続先、更新チャネル、組織ポリシーに依存する。本調査は主要な利用機能の比較であり、PowerPoint の全コマンド・全 OOXML 要素の網羅調査ではない。

## 結論

AISlide は、静的な報告書や説明資料をネイティブ PPTX として作成する基盤を持つ。一方、PowerPoint を代替するには、日常の細かな編集、外部 PPTX との往復編集、発表、共同作業、運用・保護で大きな差がある。

当初の目的である「美しく、編集と再配布が容易な PPTX」に対しては、**リッチテキスト、配置操作、表・グラフ編集、往復編集の安全性、配布・復旧**を先に進めることを推奨する。動画・3D・共同編集まで一度に取り込む必要はない。保護付き文書を必須とする利用環境については、機能追加より先に正規のアクセス方法と運用境界を決める。

以下に **46 項目**を列挙する。これは開発候補を扱いやすい単位でまとめた件数であり、互換率や達成率の分母ではない。優先度・開発順は提案で、工数・期限・採用方針は未確定。

## 調査方法と判定

- 現行の対応表に加え、通常の `open_presentation` 経路、モデル、保存処理、Studio UI、SDK を静的に確認した。旧 `import_pptx` 経路の制約だけで現在の対応状況を判定していない。
- Microsoft の公式機能比較、ファイル形式、Copilot、文書検査、保護・共同作業に関する資料と照合した。公式資料にも世代差があるため、古い配信サービスなどの記述は現行の開発候補に採用していない。
- 重ね順、ノート、マスター／レイアウト追加、スライド寸法の 4 制約を、合成データと実際の SDK・共有コアで確認した。PPTX はメモリ上のみで処理し、利用者のファイルや Office は操作していない。
- それ以外は主として静的確認であり、PowerPoint の全機能を今回実機操作した結果ではない。既存の限定的な Office 検証を、任意の PPTX の表示互換保証とは扱わない。

| 判定 | 意味 |
| --- | --- |
| 部分対応 | 基本機能はあるが、書式、編集単位、UI、再読込後の操作などに不足がある |
| 未実装 | 当該用途を完結できる公開モデル・操作・UI がない。汎用 JSON 操作や画像化による代用とは区別する |
| 保持のみ | 元パッケージの未変更データを保持する設計。表示・再生・編集・内容の安全性を保証する意味ではない |
| 意図的制約 | 原本保護、非実行、認可、資源上限などの方針に由来する。単純な制限解除を推奨しない |

優先度: **P1** = 次期の編集・互換基盤、**P2** = 基盤後の表現・利用拡張、**P3** = 必要性に応じた後続機能、**判断** = 製品方針・権限・安全性の合意が先。P1 全項目を一度に実装する意味ではない。

表の `Cxx` は末尾の実装根拠、`Mxx` は Microsoft 資料を示す。

## F. AI・デザイン支援

PowerPoint 側の主な根拠: M09。AISlide の主な根拠: C03、C08、C10。

| ID | PowerPoint の機能 | AISlide の現在地と具体的 Gap | 判定 | 優先 |
| --- | --- | --- | --- | --- |
| G45 | Copilot による対話型の作成・修正 | モデルによる新規報告生成、アウトライン指定、MCP による個別編集はある。Studio 内での継続対話、選択範囲への修正提案と差分承認、Word 文書の構造・画像や認可済み組織文書を参照する統合ワークフローは不足。外部エージェントの手作業を製品機能とは数えない。C03、C10 | 部分対応 | P2 |

## 実行で確認した境界

2 個の矩形とノートを持つ合成文書を新規作成し、SDK から操作した。新規文書での重ね順変更と Undo は成功した。その文書を PPTX としてメモリ内でエクスポート／再読込した結果は以下のとおり。

| 確認 | 実際の結果 | 関連 Gap |
| --- | --- | --- |
| 既存オブジェクトの重ね順変更 | `Unsupported: reordering existing native objects is not supported yet` | G09 |
| ノート本文変更 | `Unsupported: native notes editing is not supported yet` | G27 |
| 有効なマスターと対応レイアウトの組を追加 | `Unsupported: changing native master/layout counts is not supported yet` | G23 |
| 幅を 960 に変更 | `Unsupported: expected scene version 1, 1280 x 720` | G22 |

各拒否後に文書ハッシュ不変を確認し、最後の無変更エクスポートも元 PPTX と一致した。制約があることと、失敗時に文書を壊すことは別である。最初のマスター試験入力には対応レイアウトがなかったため、モデルの妥当性検査が先に働いた。有効な組で再実行して上表の保存経路の制約を確認した。

## 次期開発への提案

### 先に決める利用境界

1. 当面は「高品質な静的 PPTX の作成・編集」に集中するか、発表まで AISlide で完結させるか。前者なら G30-G34 を後回しにできる。
2. 標準で非暗号化の PPTX を扱える利用環境か、保護付き資料が必須か。後者なら G42 の認証・権利・ポリシー対応を導入前提として検討し、保護回避を実装しない。
3. PowerPoint 由来の既存資料をどこまで編集対象とするか。任意デッキ対応か、指定した機能・社内テンプレート群の対応かで範囲が大きく変わる。

### 推奨する開発順

| 順 | 開発単位 | 主な Gap | 到達点の例 |
| --- | --- | --- | --- |
| 1 | 編集モデルと往復保存の基盤 | G01、G02、G09、G23、G27、G29 | 混在書式のある文字・ノート・重ね順・合意したマスター操作が、新規作成後も PowerPoint 経由の再読込後も編集できる |
| 2 | 日常編集の操作性 | G05-G08、G13、G15 | 複数選択、整列、コピー、グループ化、表の書式、グラフの軸・連動ラベルを UI から使える |
| 3 | 配布・復旧・実務容量 | G28、G35、G37、G38、G41、G43 | 合意した実務デッキで文字と図表が再現され、PDF 配布、異常終了後の回復、配布内容の検査ができる |
| 4 | 表現と AI による仕上げ | G10-G12、G14、G18、G22、G24-G26、G45、G46 | 画像・ベクター・テンプレート・提案レイアウトの表現力を拡張する |
| 別トラック | 発表・組織連携・特殊表現 | G16、G17、G19-G21、G30-G34、G36、G39、G40、G42、G44 | 実際の利用要件に応じて採否と接続・実行境界を決める |

これは優先群であり、すべての依存関係を確定した工程表ではない。文書の読み上げ順・代替説明や出典の配布可否は、実装基盤の設計時点から考慮する。企業利用の要件次第では G42 が全体に先行する。

### 共通の受け入れ条件

- 文書機能は共有コアを所有箇所とし、Studio・SDK・MCP で異なる意味や上限にしない。操作 UI の追加だけで再読込後の保存制約が解消したと判断しない。
- 新規作成、AISlide での保存／再読込、PowerPoint での編集後の再読込を分けて試験する。対象バージョン・テンプレート・フォント・対応範囲を固定して検証する。
- ネイティブの文字・セル・グラフ値が編集可能で、非対象 XML、出典情報、未対応オブジェクトを失わない。無変更バイト一致、Undo、競合拒否も維持する。
- 日本語・長文・混在書式・密な表・ラベル・異なるスライド比率を含むコーパスで、実際の PowerPoint と Studio の描画を比較する。スキーマ適合だけを視覚互換としない。
- 容量の目標は代表ファイルと必要な枚数・画像・系列から決める。安全予算や非実行方針を単に解除しない。
- 原本を上書きしない。配布前検査は、利用者が確認した新しい出力に適用し、保護・署名の意味を損なわない。
